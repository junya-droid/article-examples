# article-examples

現論会の記事制作で生まれたデザイン・構成・コードなどの工夫を、GitHub Issuesで共有・検索するためのリポジトリです。

**[改善例を投稿する（フォームを選択）](https://github.com/junya-droid/article-examples/issues/new/choose)** ｜ **[投稿一覧を見る](https://github.com/junya-droid/article-examples/issues)**

## 改善例を投稿する

[投稿フォームの選択画面](https://github.com/junya-droid/article-examples/issues/new/choose)を開き、「記事の改善例」を選んでください。フォームが開いたら、タイトル、記事の型、実例・出典、工夫の内容と狙いを入力してください。**タイトルは工夫の内容が伝わる言葉で自由に付けられます。`[改善例]`などの決まった接頭辞は不要です。**

原則として**1つの工夫につき1投稿**とし、投稿は任意です。記事の種類を問わず使える工夫は、記事の型で「汎用」を選択してください。

## 改善例を活用するとき

人が参考にする場合も、AIが参照する場合も、次の手順を基本とします。

1. 今回の記事の型に合う投稿に加え、「汎用」の投稿も確認します。
2. 関連する投稿だけを読み、工夫の内容・狙い・実例・画像・コード（あれば）を確認します。無関係な投稿をすべて読んだり、複数の事例を無条件に組み合わせたりする必要はありません。
3. 取り入れたい点と、効果が未確認の点・承認が必要な点を整理します。今回の記事に合わなければ、採用する必要はありません。
4. 実際の記事制作では、[執筆ルールの正本（WRITING.md）](https://github.com/gengakusha/web-writing/blob/main/WRITING.md)、指定された準拠記事、WordPressで許可されている変更範囲を優先します。

## 正式なルール・テンプレートへの反映

このリポジトリは、記事制作の工夫を参考例として蓄積・検索するための試作です。投稿された改善例を、すべて既存のテンプレートへ追加するものではありません。

正式なルールやテンプレートの変更が必要になった場合のみ、従来のレビュー・PR・WordPressの管理手順に従って対応します。**Issueのクローズや文書PRのマージは、WordPressへの反映完了を意味しません。**
